# 并发会话与 tab 状态

Pine 的会话执行生命周期属于项目窗口，tab 只负责导航和展示。切换、打开或关闭 tab 不得隐式停止会话；用户停止某个会话、删除会话或关闭项目才会释放对应执行资源。

## 主进程

`ProjectRuntimeRegistry` 为每个窗口维护 `liveSessions`，按 `sessionId` 保存会话摘要、上下文用量和批准模式。事件通过该映射找到所属窗口；后台会话保留相同的事件路由。

- 新建请求各自创建实例，不复用窗口级的创建锁，也不释放其他会话。
- 同一会话的重复打开共用 `openingSessions` 中的 promise。
- 停止、压缩、撤回 steering 和更新批准模式的 IPC 必须携带 `sessionId`，并验证会话属于请求窗口。
- 批准和问卷按 `requestId` 验证所属窗口，并记录会话归属。会话结束、失败或删除时，只清理该会话的待处理请求。
- 关闭项目先移除窗口归属，等待正在创建和打开的实例完成，再统一释放所有实例及项目服务。晚到的创建结果不能进入新的项目。

`focusedSessionId` 仅用于现有 MCP 状态查询的显示选择。MCP 配置更新会刷新窗口内全部会话；执行控制的 renderer IPC 不依赖该选择。

目前多个 `PineAgentRuntime` 会话仍在同一个 Electron utility process 内并发执行。这次模型解决会话生命周期和状态归属问题；没有引入每会话一个 OS 进程。utility process 崩溃仍是共享故障边界。

## Renderer

Pinia 的 session store 为每个 `sessionId` 保留一个响应式状态对象，包含消息、历史分页、加载状态、运行状态、上下文用量、steering、批准、问卷和自动审核状态。消息与工具调用索引也属于该对象。

事件无论前台或后台都更新所属会话。`activeSession` 等旧接口只是当前会话的计算投影；保留的 `ProjectSessionView` 直接按自身 `sessionId` 读取状态，不缓存另一个 tab 的投影。draft 的输入、附件、批准模式和提交状态属于各自视图。

历史请求捕获目标状态对象，晚到的结果更新原会话。合并时保留已收到的实时消息，避免磁盘快照覆盖新内容。同一会话的历史请求复用 promise，其他会话不受阻塞。项目重置通过 epoch 使旧的 resume 和 prompt 结果失效。

关闭运行中的 tab 会保留会话状态，以便重新打开时继续显示运行和待批准状态。

## 用户交互

批准和问卷组件以 `requestId` 为 Vue key，新请求建立独立组件状态。响应同时指定 `sessionId` 和 `requestId`；发送中的请求由 store 去重，成功后只移除对应请求，发送失败保留批准卡供重试。后台批准卡不处理全局快捷键。

## 验证

相邻 `__tests__` 覆盖并发创建、重复打开、项目关闭期间的晚到结果、后台消息/批准/问卷、快速切换期间的历史加载、按会话执行控制、重复响应、响应失败重试和连续批准卡。

提交前运行 `bun run check`。这些测试验证状态模型和 IPC 路由，不能替代真实 provider 下长时间并发工作的桌面端验证。
