# 本地网页控制

在 Pine 设置的「远程控制」分类中开启「浏览器访问」、修改端口，然后点击「在浏览器中打开」或「复制链接」。默认端口为 `9415`，只监听 `127.0.0.1`。需要保持 Pine 进程运行；它不是独立的服务端或多用户服务。

## 边界

```text
桌面界面 → createPineApi → preload IPC ─┐
                                     ├→ PineRequestRouter → 项目/会话服务 → AgentHost → utility process
网页界面 → createPineApi → HTTP/SSE ───┘
```

- `client/pineApi.ts` 定义同一套类型化应用调用，传输接口只负责请求、发送和事件订阅。preload 仍是桌面渲染进程访问主进程的唯一入口。
- `main/requestRouter.ts` 的上下文只有客户端标识和来源，不伪造 Electron 事件，也不向网页暴露 `ipcRenderer` 或原始 worker 消息。诊断追踪在路由器内完成，桌面和网页请求同样记录。
- `main/webRequestPolicy.ts` 用一张表声明网页可调用的每个通道：需要附着的项目范围、是否可安全重复，以及网页特有的前置检查（`prepare`）或替代处理（`handle`）。新增 IPC 方法默认不对网页开放；网页语义只在这张表里调整，`WebApplication` 不按通道名特判。业务参数仍由共用处理器验证。
- `main/localWebServer.ts` 负责 HTTP、登录、资源传输、SSE、慢连接处理和命令回执，不读取项目文件或执行 Agent 操作。
- `main/webApplication.ts` 负责浏览器与已有项目服务的适配，包括附件上传、资源授权、设置持久化和服务生命周期。
- `main/webSubscriptions.ts` 隔离不同浏览器页签的文件订阅。网络连接中断不停止 Agent；废弃订阅在重连宽限期结束后释放。

HTTP 请求、响应和事件统一使用 `shared/webControl.ts` 的 JSON 编解码，`Uint8Array` 以显式标记传输，不由单个通道手工解码。

窗口、全局快捷键、原生材质和安装更新属于桌面能力。网页不调用这些能力。网页选择的文件会上传到 Pine 管理的项目附件目录；项目文件夹则使用运行 Pine 的电脑上的路径。文件和会话导出通过浏览器下载。

## 会话与连接生命周期

打开项目时，桌面和网页走同一个处理器：桌面窗口之间仍把项目交给已持有它的窗口；网页附着在已有运行时旁边，不接管窗口。`ProjectRuntimeRegistry.share()` 让多个客户端引用同一个项目运行时。共享客户端打开同一会话时复用已有实例和打开中的 promise，不会再次启动 Agent。项目创建、共享和设置刷新按项目串行执行。

关闭一个桌面窗口只移除该窗口的引用；网页服务仍持有的运行时继续执行。浏览器页签关闭或刷新不释放网页服务持有的运行时。用户关闭网页服务时，释放网页的引用、监听和临时授权；仍由桌面持有的运行时继续存在。删除项目会释放所有客户端的引用。网页访问随 Pine 进程结束；在 Windows 和 Linux 上关闭最后一个窗口即退出，不会留下没有窗口的后台进程。批准和问卷按待处理请求及其所属会话验证，共享客户端中只有首个有效响应生效。

## 状态恢复

Pi JSONL 仍是持久会话历史的来源。网页服务不维护第二份会话文件。

服务未运行时不记录任何网页状态，也不序列化事件，纯桌面使用没有额外开销。启用服务前已在运行的会话从持久历史加后续事件恢复。

`WebSessionState` 从已有事件压缩出运行中消息、工具状态、上下文用量和待处理交互。每种会话事件都必须在穷举的分类里声明是否保留；一次性通知（如会话迁移、重置）不进入快照，重连时不会重复生效。新连接获取快照，随后继续接收事件。断线重连优先使用 SSE 游标补发有界事件日志；游标失效时重新获取快照，并与持久历史合并。SSE 快照和后续事件在同一事件循环内交接。

HTTP 请求 ID 与业务回执关联；网络重试复用原 ID。查询可以直接重复执行；有副作用的调用保留有界回执；回执表满时淘汰最早完成的回执，只有全部仍在执行时才拒绝新请求，避免响应丢失后再次提交 prompt 或执行操作。待处理调用不会因回执过期被重复执行。

## 访问与文件

设置只持久保存启用状态和端口。每次启动监听生成新的访问令牌；链接通过 URL fragment 传递令牌，再交换为 `HttpOnly`、`SameSite=Strict` Cookie。Cookie 名包含端口，因为浏览器的 Cookie 不区分端口。服务器验证回环 Host 和写请求 Origin，不开放跨域访问，静态资源和 API 均需要登录。修改端口失败保留原监听；保存设置失败回滚监听配置。

媒体预览继续使用已有路径解析、项目文件夹限制、外部展示授权和字节范围读取。浏览器资源使用 HTTP 地址；附件数据和会话消息不因传输方式改变。上传保存为服务端生成的文件名，原文件名仅用于显示。网页不能通过构造附件消息把任意宿主机路径变成新的读取授权。

## 验证

相邻 `__tests__/` 覆盖请求白名单、真实 HTTP 鉴权、重复提交、SSE 补发、端口冲突与释放、共享运行时、批准响应、快照压缩、页签订阅及静态文件越界。完整检查为 `bun run check`；HTTP 测试需要允许绑定本机回环端口。
